# Référence Complète de l'API REST Vectispire

Ce document constitue la référence officielle et exhaustive des interfaces de programmation REST exposées par le Control Plane **Vectispire** (v4.1.0).

---

## 🔒 Sécurité et Authentification

L'API Vectispire utilise trois mécanismes d'authentification selon le type d'appelant :

### 1. Jeton de Session Utilisateur (`Bearer JWT`)
* **En-tête** : `Authorization: Bearer <token>`
* **Utilisation** : Interface Web Angular, sessions d'utilisateurs interactives.
* **Obtention** : Via `POST /api/v1/auth/login` (avec support éventuel du 2FA/TOTP via `POST /api/v1/auth/mfa/verify`).

### 2. Clé d'Agent de Scan (`X-Agent-Key`)
* **En-tête** : `X-Agent-Key: <agent_key>`
* **Utilisation** : Protocoles d'agents distants distribués (`/api/v1/agent/**`).

### 3. Clé d'API Programmatique (`X-API-Key`)
* **En-tête** : `X-API-Key: <api_key>`
* **Utilisation** : Pipelines CI/CD (GitHub Actions, GitLab CI), intégrations SIEM et scripts d'automatisation.

| **OWASP** | `GET` | `/api/v1/owasp/coverage/weekly` | Compte | La grille semaine par semaine (semaines ISO, lundi 00:00 UTC), de la plus ancienne à la plus récente : par semaine `weekStart`, `reconstructed`, `capturedAt`, `categoriesMeasured`, les totaux `open`, `settled`, `opened`, `resolved`, `reopened`, et par catégorie `category`, `title`, `state`, `open`, `settled`, `opened`, `resolved`, `reopened` ; en tête, `reopenedRecordedFrom`. `from` / `to` sont des dates ISO lues comme le lundi de leur semaine ; par défaut les 12 dernières semaines jusqu'à la semaine courante, un `to` postérieur à la semaine courante est lu comme celle-ci, 52 semaines au plus (400 au-delà, et pour un `from` postérieur à `to`). `project_id` **ou** `solution_id` en option (les deux : 400) ; un périmètre inexistant ou dont l'appelant ne voit rien répond 404, « Project not found. » / « Solution not found. ». Les chiffres portent sur les cibles visibles de l'appelant dans le périmètre. Une semaine que l'enregistrement hebdomadaire a capturée porte l'état enregistré `state`, `open` (non réglées, à la dernière capture de la semaine) et `settled`, combinés sur les cibles comme la grille les combine : une catégorie qu'une cible a mesurée compte les constats de toutes les cibles — ceux d'une cible jamais analysée compris — et vaut `FINDINGS` si leur somme dépasse zéro, sinon `NO_FINDING` ; `NOT_COVERED` si toutes les cibles le lisent ; sinon `NOT_MEASURED`, sans rien compter. La semaine en cours lit donc ce que `GET /api/v1/owasp/coverage` lit pour le même appelant. Une semaine antérieure — ou une semaine que la fenêtre des preuves (`evidence_retention_days`) a purgée du relevé — est **reconstituée** à partir des dates des issues : `state` et `settled` valent `null` — jamais calculés aujourd'hui pour hier, et le triage d'une date passée n'est pas connu — et `open` compte toute issue rangée dans la catégorie ouverte à la fin de la semaine, quel que soit son triage — hors d'une résolution antérieure qu'une réouverture a consignée dans l'historique de l'issue. `opened` et `resolved` viennent des dates sur chaque semaine, rangées comme la grille range les issues, sans ses interrupteurs de mesure ; `resolved` compte aussi une résolution antérieure qu'une réouverture a consignée, une issue une fois. Limite connue : une réouverture antérieure à cette version n'a rien consigné, et une telle issue ne garde que sa dernière résolution : elle compte comme ouverte entre cette résolution antérieure et sa réouverture. `reopened` compte les issues rangées dans la catégorie qu'une réouverture consignée dans l'historique de triage a ramenées pendant la semaine, une issue une fois — ce qui fait monter `open` sans `opened` correspondant. **Il vaut `null` sur une semaine commencée avant que les réouvertures soient consignées** : avant V68 une réouverture n'écrivait rien, et zéro affirmerait qu'il n'y en a pas eu. Le début de l'enregistrement est daté par l'application de V68 dans l'historique de Flyway, plus un jour — la colonne ne porte pas de fuseau, et un jour plus tard n'est jamais trop tôt — et `reopenedRecordedFrom` est le lundi de la première semaine qui a le chiffre (`null` si aucune ne l'a). Chaque chiffre ouvre sa liste sur `GET /api/v1/issues` avec le même rangement — un total avec `owasp_category=any`, une barre de réouvertures avec `reopened_from` / `reopened_to`. Pas de clé d'intégration. |

## 🛠️ Exemples d'Appels cURL

### 1. Connexion et Récupération du Jeton
```bash
curl -X POST "https://vectispire.example.com/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "MonSuperMotDePasse"}'
```

### 2. Déclenchement d'une Analyse de Dépôt
```bash
curl -X POST "https://vectispire.example.com/api/v1/repositories/1/scan" \
  -H "Authorization: Bearer <VOTRE_JWT_TOKEN>"
```

### 3. Consultation de la Surface d'Attaque
```bash
curl -X GET "https://vectispire.example.com/api/v1/attack-surface" \
  -H "Authorization: Bearer <VOTRE_JWT_TOKEN>"
```

### 4. Téléchargement du SBOM d'une Analyse
```bash
curl -X GET "https://vectispire.example.com/api/v1/scans/42/sbom" \
  -H "Authorization: Bearer <VOTRE_JWT_TOKEN>" \
  -o scan-42-sbom.json
```
