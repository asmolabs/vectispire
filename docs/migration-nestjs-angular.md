# Porting Zanshin to NestJS + Angular

**Status: done.** The Python/Reflex tree has been removed; the control plane, the scan
execution and the UI are all TypeScript. This document is the record of that port — what
was kept, what was dropped, what was fixed along the way, and the invariants it left
behind.

The week-by-week plan this file used to carry has been executed and is not reproduced;
`git log docs/migration-nestjs-angular.md` has it.

## Why it happened

Not a defect in Python — the up-front analysis concluded Python was the right language for
this domain — but **Reflex**:

- a client's state lived on the instance that accepted its socket, so a second web instance
  required Redis, and a startup guard existed to refuse the deployments that broke;
- four silent CSS failures in one afternoon, including a typography that died twice (CSP
  refusal *and* an overwritten Radix variable);
- typing did not cross the Python/JS boundary: `.get("critical", 0)` on a dataclass,
  `r["findings"] == "0"` compared against a string.

The choice was an Angular front end (Sakai + Optimus UI) and a NestJS back end, for one
language end to end and an API that actually exists.

The number that drove the schedule: **tests were 41% of the project**, 1.72 lines of test
per line of service. They did not encode trivia — they encoded the triage life cycle, the
issue fingerprint, transactional claiming, and six portability defects that were invisible
both to a reading and on SQLite.

## The plan's central decision, and why it was reversed

The plan's structuring bet was: **scan execution stays in Python, and the agent protocol is
the seam.** `scan_contract.py` imported nothing from Zanshin, `Dockerfile.agent` installed
neither Reflex nor SQLAlchemy, and NestJS only had to implement four HTTP routes for the
existing Python agent to keep working unmodified. That would have spared 1,500 lines of
hard-won container hardening — pinned digests, network off, memory and PID caps — in a
place where TypeScript brings nothing, the Node Docker SDK being less mature than its
Python counterpart.

**It was not followed.** The scanning layer was ported too (`backend/src/scanning/`), and
the Python tree removed entirely. What that bought: one language end to end, and the
single-process deployment the plan expected to lose — the plan's own text noted that
keeping Python meant "at least one agent container alongside", which would have been a real
operational change.

What it cost is recorded in the register rather than here:
[decision 0001](architecture/decisions/0001-pluggable-scan-layer.md)'s pluggable scan layer
came across as a single concrete class, its two other implementations and its contract test
lost with the Python tree.

## The differential bench

This is the piece that made the rewrite verifiable, and it is why the port did not silently
change a formula.

A generator produced, **from the real Python code**, the values the TypeScript stack had to
reproduce. The files landed in `backend/test/vectors/`, committed, since the TypeScript CI
had no Python interpreter. Two safeguards framed it: a Python test checked that the
committed files still matched what the Python code produced that day, and that the
functions copied into the generator had not drifted from their originals; and the Jest
suites replayed them.

| Vectors | Content | Generated by |
|---|---|---|
| `issue-fingerprint.json` | 8 issue fingerprints | a verified copy of `build_fingerprint` |
| `exports.json` | 25 SARIF / OpenVEX / CSV documents | **the real `exports`**, imported |
| `policy-gate.json` | 20 verdicts, 14 tightenings | **the real `policy_gate.evaluate`**, imported |

Where the Python code imported without opening a connection, the generator imported the
original rather than recopying its logic. Forty lines of nested rules copy badly; five
lines of hashing copy well, and the copy was then confronted with the original by a test.

## The five traps that destroy data

These outlived the port. They are invariants, not implementation details.

1. **The fingerprint is a data contract.** SHA-256 of
   `repo:{id}|{type}|{identifier}|{purl or name}|{file_path}`. It deliberately excludes the
   package **version**, `is_direct_dependency` and the **line**. A one-byte divergence — a
   separator, an order, a case — restarts the **entire** backlog as "new" and destroys
   every triage decision. Locked by a fixed-vector test.

2. **The encryption's key derivation had to be reproduced byte for byte.** The Python
   service derived no KDF: it **truncated to 32 bytes or padded with NULs**. That was
   deliberate — changing the derivation would have made everything existing undecryptable.
   AES-GCM **and the contextual AAD** (`private_key_context(key_id)`) had to be reproduced
   too, that being what stops the encrypted blob of SSH key A being copied into row B to
   clone repository A with B's key. Plus the no-AAD fallback for older values, and
   multi-key rotation.

3. **`null` is not `[]`.** In `ScanArtifacts`, `[]` means "the analysis ran and found
   nothing" — which **resolves** the corresponding issues; `null` means "it did not run" —
   the backlog is left alone. The same distinction governs the scanned-types list. A port
   that normalized nulls into empty lists would silently resolve hundreds of security
   issues, with no error anywhere. TypeScript's typing helps here, on condition that no
   deserialization fills the defaults in.
   ([decision 0007](architecture/decisions/0007-none-is-not-an-empty-list.md))

4. **The audit log's chain.** See below — this one was reconstructed rather than
   reproduced.

5. **The outbox and the issues share a transaction.** The notification has to become
   durable at the same instant as what it describes. In TypeORM that means an explicit
   interactive transaction, not two successive calls.

## The audit chain was reconstructed, not reproduced

The Python implementation hashed the timestamp in the form `datetime.isoformat()` produces:
fraction omitted when the microseconds are zero, six digits otherwise. That coupled a
security control to a language's formatting, and made verification sensitive to how an
engine renders its dates — `.123` and `.123000` denote the same instant and gave two
different hashes.

The chain was therefore **rebuilt** on a canonical form (`YYYY-MM-DDTHH:MM:SS.sssZ`,
fraction always present). Two accepted consequences: hashes written by Python no longer
verify, and the chain no longer certifies ordering below the millisecond — which nothing
depended on, two entries in the same millisecond still being distinguished by their content
and by the previous entry's hash.

The switchover operation is `rebuildChain()`
([`backend/src/domain/audit/audit-hash.ts`](../backend/src/domain/audit/audit-hash.ts)):
read every entry oldest to newest, recompute `previous_hash` and `entry_hash`, write. It
does not touch entry content, and it is idempotent.

It is to be run **once, with somebody watching**. Rewriting an integrity log is precisely
what that log exists to make detectable: it must never be triggered automatically, not at
startup, not by a route.

## What the port found

Things found by building, that would not have been found by reading.

**`node-postgres` breaks timestamps twice.** It returns a `Date`, which loses the
microsecond, and applies the machine's timezone to a timezone-less column holding UTC.
Fixed in `backend/src/persistence/pg-types.ts`, verified against a real PostgreSQL.
**Independent of Python**: it would be true of a TypeScript stack written from scratch, and
the timezone shift is zero on a machine in UTC, hence invisible in development and in CI.

**`primeicons@8` is no longer MIT.** Pinned to exactly `7.0.0`.

**Sakai loaded a font from a CDN**, which Zanshin's CSP refuses — the trap that had already
killed the typography on the Reflex side. `frontend/scripts/check-assets.mjs` now refuses
it.

**Two defects in the Python code, fixed in passing**: `ScanRepository.count_by_queue_state`
raised a `NameError` on every call, and the agent task builder omitted `run_sast`, so no
remote agent ever ran Semgrep.

## What was deliberately dropped

- **The OSV.dev and HTTP side-car scan back ends.** The side-car was already documented as
  redundant with remote agents, which do the same thing with a better trust boundary; OSV
  matching bought little that a pinned Grype image does not.
- **The Semgrep rule fetch script**
  ([decision 0006](architecture/decisions/0006-semgrep-rules-written-here.md)). Installing
  an upstream rule set is a manual step for now.
- **The startup refusal of a second instance on SQLite.** Not a choice so much as an
  omission; it is recorded as open in
  [04](architecture/04-runtime-and-deployment.md).

## Risks stated at the time

- **Optimus UI was at 1.0.1**, a community fork of PrimeNG v21 born of PrimeTek moving to a
  commercial license. The licensing choice is the right one — MIT, redistributable,
  consistent with an open source project — but the UI leans on a young project. The
  reasonable fallback if the fork stalls: Angular Material, at the price of giving up
  Sakai.
- **The npm dependency tree** is an order of magnitude larger than `uv.lock`. For a
  security tool that is a point to own explicitly, and to instrument.
- **Six months without a new feature.** That was the real cost. A plan that ignores it is
  not a plan.
