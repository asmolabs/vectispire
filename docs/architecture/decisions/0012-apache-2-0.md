# 0012 — Apache-2.0, and the AGPL was the alternative

**Date:** 2026-08-22 · **Status:** accepted · **Decider:** Laurent Boucher

> Written the day the licence was chosen, because a licence is the one decision in this
> register that gets harder to change every week rather than easier. After a hundred commits
> it is a conversation with one copyright holder; after ten contributors it is a conversation
> with ten, and any one of them can say no.

## Context

The repository had no `LICENSE` file. That is not a neutral state: absent a licence, the
default is exclusive copyright — nobody may copy, modify or run it, and every reader who
found the code was legally worse off than if it had been closed on purpose. The `docs/`,
the ADRs and the README all address a reader who is expected to fork and audit, and none
of them were true.

Two constraints were checked before the choice rather than after.

**Nothing in the dependency graph forces a licence.** The compile classpath is Apache-2.0
and MIT throughout — Spring Boot, Jackson, PDFBox, Liquibase, docker-java, Hibernate 6 (which
left LGPL behind), JGit under the EDL, Bouncy Castle under an MIT variant, and the whole
Angular side. No copyleft is linked.

**The two copyleft drivers are `runtimeOnly`, and that is what saves them.** MySQL
Connector/J is GPL-2.0 with Oracle's Universal FOSS Exception; MariaDB Connector/J is
LGPL-2.1. Neither is on the compile classpath, no Vectispire class references a driver, and the
connection arrives through the JDBC API. The FOSS Exception's list of permitted licences
includes Apache-2.0, which is what makes shipping the MySQL driver inside an Apache-2.0
image lawful — and there is now a production install on MySQL, so this is a live constraint
and not a note about portability.

**The scanners are processes, not libraries.** Syft, Grype, checkov, gitleaks and Semgrep OSS
run in ephemeral containers, invoked by command line, pulled at run time from their own
publishers. Semgrep OSS being LGPL-2.1 reaches nothing here. The rules are the real licence
question in this codebase and [0006](0006-semgrep-rules-written-here.md) already decided it.

## Decision

**Apache License 2.0**, whole repository, backend and frontend.

Two clauses are the reason it is Apache rather than MIT. **Clause 3 grants patents
explicitly** — which is what a corporate legal review looks for before authorising an
internal deployment, and its absence from MIT is a silence they have to resolve by
guessing. **Clause 5 makes a contribution licensed under the same terms by default**, so
patches can be merged without a CLA for as long as no relicensing is contemplated.

It is also the licence of the ecosystem Vectispire sits in — Syft, Grype, Trivy,
Dependency-Track are all Apache-2.0. A security tool that asks to be audited should not make
its own licence the first surprise.

## Why not AGPL-3.0

This was the real alternative, and it was rejected on a judgement rather than on a fact, so
the judgement is written here instead of the conclusion.

Vectispire is a self-hosted web application: the exact case the AGPL was written for. Under
Apache-2.0, somebody may run Vectispire as a paid hosted service, modify it, and owe nothing
back. The AGPL closes that; Grafana and Mattermost both closed it that way.

It was rejected for two reasons that point the same direction. **The AGPL costs adoption
precisely among the readers this project is aimed at** — many enterprises forbid AGPL
software outright, including for internal use, and an ASPM dashboard that a security team
cannot get approved is a dashboard nobody runs. **And it would force a CLA immediately**: a
future open-core edition needs the right to relicense contributions, which under AGPL without
a CLA means asking every past contributor. Choosing AGPL means choosing the CLA on the same
day, and a CLA is itself a barrier to the first drive-by patch.

That trade is a bet on adoption over hosted-service protection. **If the bet turns out
wrong — if somebody does resell Vectispire hosted, and it matters — this decision is the one to
supersede**, and the cost of superseding it is the point of this paragraph: relicensing needs
the agreement of every copyright holder at that moment. The cheap moment to change course is
while that is one person.

## What was rejected

**MIT.** Shorter, and understood by more people. Rejected for the patent silence: for a
tool whose scanning behaviour touches other people's code and images, an explicit grant is
worth the extra pages.

**LGPL-2.1, as SonarQube uses.** It protects a library boundary. Vectispire has none — it is an
application, not something anybody links against — so the clause that does the work would do
no work here.

**A source-available licence (BSL, Elastic v2).** These would answer the hosted-service worry
better than the AGPL does, and they are not open source. The question asked was which open
source licence to use; answering it with something that merely looks like one would be the
kind of thing this application flags in other people's dependencies.

**Per-file copyright headers.** Not applied, to 386 Java files and 56 TypeScript ones. Apache-2.0
does not require them — clause 4 asks for the licence and the `NOTICE` to travel with the
distribution, which the `Dockerfile` now does — and a header in every file is 442 lines of
churn that ages badly the first time a year changes or a name is added. If a downstream ever
needs per-file provenance, `reuse`-style headers can be generated then, mechanically.

## Consequences

**`NOTICE` is now part of the distribution, and it has to stay true.** It names the two
copyleft drivers by module and licence. A new dependency under an unusual licence, or moving a
driver from `runtimeOnly` to `implementation`, changes the legal position and not just the
build file — the paragraph next to the MySQL entry says so where somebody editing the list
will read it.

**The image carries `LICENSE` and `NOTICE`.** Shipping the code without them is precisely the
finding Vectispire reports on other people's containers.

**Nothing enforces any of this yet.** There is no check that a new dependency's licence is
compatible, and no test asserts the `NOTICE` matches the resolved dependency graph — which is
uncomfortable in a codebase whose own rule is that a guarantee nobody executes is not a
guarantee. Vectispire already owns the mechanism: it evaluates a licence blocklist against the
SBOM it generates, and the `supply-chain` job in CI already builds that SBOM of the jar that
ships. Pointing the blocklist at Vectispire's own SBOM is the obvious next step and is not done
here. Until it is, the `NOTICE` is held by discipline, and this sentence is what stops that
from being mistaken for a check.

**The name is not licensed.** Apache-2.0 clause 6 grants no trademark rights, deliberately: a
fork may use the code and may not call itself Vectispire. That distinction only survives if the
name is actually claimed somewhere, which is a separate piece of work.
